This page maps Leash's shipped surfaces to the hackathon's judging criteria. Each row points at the docs and in-repo evidence that explain the feature.

<Note>
  Read this alongside the [Hackathon overview](/hackathon/overview) (what Leash
  is and which track it targets), the [QVAC-only
  proof](/hackathon/qvac-only-proof) (the hard gate every row depends on), and
  [Design decisions & tradeoffs](/hackathon/design-decisions) (the engineering
  judgment behind these rows — what we weighed, chose, and disproved).
</Note>

## Hard gates

These are pass/fail prerequisites, not scored dimensions:

| Gate                                                 | How Leash meets it                                                                                                |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| QVAC SDK for all inference/embeddings/RAG/multimodal | Every AI path routes through `@qvac/sdk` → local serve. No cloud AI. [Proof →](/hackathon/qvac-only-proof)        |
| Track hardware constraints                           | General Purpose, ≤32 GB consumer-device usage. The final public-provider stress run peaked at 24,891 MB system memory on the approved 36 GB Mac, below the agreed 32 GB ceiling. [Overview →](/hackathon/overview) |
| Reproducibility & out-of-the-box setup               | Documented run path + warm-cache; physical Android Release cold-launched in airplane mode, and a WAN-denied requester completed public inference against a Pro QVAC serve whose own outbound network was sandbox-denied. [Evidence →](/hackathon/evidence-and-reproducibility) |
| Structured audit log                                 | JSONL records of model loads, prompts, tokens, TTFT, tok/s. [Evidence →](/hackathon/evidence-and-reproducibility) |
| Open-source license                                  | **Apache-2.0** across the workspace.                                                                              |

## Scored criteria

| Criterion                                                           | What addresses it                                                                                                                                                                                                                                                                     | Reference                                                                                                                         |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| **Innovation**                                                      | A personal AI harness over a connected runtime: local perception (notes, voice, OCR/photos, screen activity, feed), free private-mesh delegation, signed discovery of unpaired zero-price public QVAC providers, and an on-device nightly LoRA loop — not a single-feature demo. Public paid inference remains an economy design seam, not a shipped paid route. | [The agent economy](/explanation/the-agent-economy), [Memory loop](/explanation/the-memory-evolution-loop)                        |
| **Capabilities (multi-agent, tool calling)**                        | General-purpose by extension: a skills-first harness with `run_skill` sub-agents, deterministic step pipelines, plan mode, proactive feed/heartbeat behavior, human-approved tool calling, MCP integrations, and specialist delegates.                                                | [The skills harness](/explanation/the-skills-harness), [Multi-agent](/agents/multi-agent), [Orchestration](/agents/orchestration) |
| **Performance (P2P load distribution, constrained devices, speed)** | Final public Mac→Mac QVAC benchmark: 8/8 sequential jobs, 1,013/1,047 ms p50/p95 total latency, 140/312 ms requester TTFT, 111/214 ms provider TTFT, 39.56/39.85 tok/s, and 24,891 MB peak provider-system memory. A four-request burst admitted one job and rejected three as `overloaded_provider`, proving the concurrency limit rather than silently falling back. Physical iPad and Android Release clients also completed public Mac inference with correlated provider-side audit evidence. | [How the mesh routes work](/explanation/how-the-mesh-routes-work), [Evidence](/hackathon/evidence-and-reproducibility) |
| **Model usage & coverage**                                          | Six+ QVAC models in daily use — `qwen3-4b`, `embed`, `classifier`, `health` (MedPsy), `qwen3vl`, `ocr`, `parakeet` (STT), and `supertonic` (TTS).                                                                                                                                     | [Models and the catalog](/explanation/models-and-the-catalog), [Models reference](/reference/models-and-aliases)                  |
| **Complexity & UX**                                                 | Tabbed dashboard (chat, Brain, Models, Tasks, Economy, Feed, Services, Settings), AI Elements chat, voice call mode, a desktop app, and a broadsheet landing site.                                                                                                                    | [Leash and its surfaces](/explanation/leash-and-its-surfaces)                                                                     |
| **Evidence quality**                                                | Consistent JSONL audit evidence, smoke tests, a commit-mapped changelog, and a full Diataxis docs site.                                                                                                                                                                               | [Changelog](/reference/changelog), [Scripts & smoke tests](/reference/scripts-and-smoke-tests)                                    |
| **Social engagement (build-in-public)**                             | The product repo preserves the technical evidence; the demo is linked as a public YouTube playlist for review.                                                                                                                                                                        | [Demo playlist](https://www.youtube.com/playlist?list=PLeERy8YL4mpQwT3OwpzOqjp23FlrLQ_1Y)                                         |

<Warning>
  A few submission-form items are external to this repo by nature: DoraHacks

</Warning>
