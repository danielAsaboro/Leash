Earn documents the optional paid public-mesh contract: publish a price, meter a completion, and settle the work done.

<Warning>
  Zero-price public inference is live. Paid public inference remains a protocol and settlement
  preview; a non-zero-price job is never silently treated as a free or local success.
</Warning>

The rule is simple:

- **Local first.** If the device can answer locally, no mesh route is needed.
- **Private mesh second.** Your private mesh is trusted personal infrastructure. Rates exist in the interface, but they are always `0`.
- **Public compute by intent.** An opted-in provider publishes signed, expiring capabilities. A
  shareable zero-price request can select it and stream a real QVAC response.

<Note>
  Membership supports one private mesh plus up to fifteen public discovery cells. Public providers
  stay untrusted and never gain private membership.
</Note>

## What earns

A provider earns when all of these are true:

- The request is safe to leave the local device and private mesh.
- The selected public provider advertises a non-zero public rate.
- The consumer pre-authorizes the maximum spend before streaming starts.
- The provider settles the metered completion after the run closes.

Free public providers still participate in routing. They advertise a `0` rate and skip the paid-session flow.

## What stays free

Private mesh delegation stays free. The runtime forces private visibility to a zero-rate policy:

- Public paid-session validation is rejected on private meshes.
- Advertised settlement rails are suppressed on private meshes.
- No x402 pre-authorization is opened.
- No settlement transaction is needed.

<Note>
  The current `/economy` ledger and replicated `SessionSettlementReceipt` path are paid-session
  first. Free public routes and private routes can still execute, but they do not yet appear as the
  same first-class economy receipt rows.
</Note>

## The routing ladder

The route ladder is:

```text
local device -> private mesh -> public mesh
```

Public mesh is the market boundary. Signed identity, eligibility, zero-price request transport, and
correlated audits are live. Payment rails, reputation, and receipts are implemented and tested as
subsystems, but non-zero-price settlement is not yet wired to the live public request transport.
